# RefSync-QA v3.2：方案、修复边界与验收

日期：2026-09-22。代码入口：`03_复赛算子/Raw_data/`。

## 1. 结论与使用建议

推荐 v3.2 的 **conservative 默认策略**：在完整数据上做检测、确定性字段修正、证据门控重对齐、稀疏估计补值、复检和连续片段治理。证据不足的修复保留为候选，不为了减少隔离数量强行放行。

本版完成代码修正、文档、全量结果清单和本地验收；不是“所有异常均可恢复”，也不是“已完成复赛平台认证”。PPT 和历史提交包没有在本轮改写。

两套策略使用同一批 20 条参考集标定、同一批 89 条测试集；仅时间戳治理策略不同：

| 实测指标 | conservative：推荐默认 | nominal：显式契约规整 |
|---|---:|---:|
| 输入测试轨迹 | 89 | 89 |
| 原始检测：未标记 / 仅价值提示 / 需复核 | 24 / 1 / 64 | 24 / 1 / 64 |
| 实际生成 Parquet 修复副本 | 8 | 15 |
| 仅元数据补丁 | 1 | 1 |
| 原需复核、复检后不再需复核 | 6（5 副本 + 1 元数据） | 13（12 副本 + 1 元数据） |
| 有最终训练片段的轨迹 | 49 | 56 |
| 实际可加载训练片段 / 帧 | 61 / 8,881 | 68 / 10,290 |
| 隔离回采 / 文件不可用 | 38 / 2 | 31 / 2 |
| 逐格审计的改写单元格 | 807 | 2,132 |
| 需人工决定的修复候选项 | 28 | 20 |
| 89 条平均质量分（前 → 后） | 85.55 → 86.49 | 85.55 → 87.78 |

nominal 比默认多得到 1,409 帧，但这些依赖“按 frame_index/fps 生成规范时间”的明确约定，**不是恢复真实采样时刻**；相关估计轨迹降权。没有该约定时，不应选 nominal 来美化通过率。两套产物分目录保存，不混用掩膜、修复副本或分数。

“8 条副本”也不等于“8 条修复成功”：ep25 仅修正存储类型仍有时间问题；ep29/48 仅中后段可用。质量分提升来自真实输出复检，但依然只是同一套规则的内在一致性证据，不是独立真值证明或模型效果提升。

## 2. 数据从哪里来

使用本地官方原始目录 `具身智能多模态数据质量检测算法赛题-初赛数据/初赛数据/`，没有重新随机划分，也没有把测试轨迹加入正常标定集。

- `参考集/`：官方给出的 20 条无异常案例，用于统计阈值标定。
- `测试集/`：官方给出的 89 条含质量隐患轨迹，没有逐轨迹/逐帧官方异常标签。
- 图片来自 Parquet 内的 `image`、`left_wrist_image`、`right_wrist_image` 原始 bytes；path 是随样本携带的图像标识，不是另从网络下载的图片。修复只重排既有 bytes，不生成场景画面。
- 合成故障只在专用测试沙箱中向参考底本注入，用于检验代码；不加入测试集实测数，不发布为真实采样数据。
- 布局由本地《比赛规则》明确给出：每臂 position-3、Rotation-6D-6、gripper-1，两臂共 20 维。元数据 `robot_type=panda` 原样保留；不据此宣称实机型号或人形硬件已验证。

完整 20 条默认阈值哈希：

`4b70fc4db785da7888fa76b7d5ccf9b9fc3bf3a9e9b5a1c8f75b4383ee25d4b4`

`calibration/default_thresholds.json` 记录 0–19 全部参考 ID、每个文件 SHA-256 和工程阈值来源。默认文件与现场 20 条重新标定另做对照；历史 v3.1 的 10 条阈值不再是当前默认。

实际对照：89 行轨迹报告的 47 个非耗时字段全部相同（仅排除 seconds）；随包阈值产物也实际加载出 61 个片段、8,881 帧。不存在用 10 条标定结果冒充 20 条实验的混用。

## 3. 流程与比赛要求映射

流程：路径/参数预检 → 发现数据与解析元数据 → 参考集标定 → 单轨迹特征提取 → 四类检测与五维评分 → 有条件修复副本 → 回读审计 → 同检测器复检 → 连续片段与同任务去重 → 掩膜、报告、训练加载验收。

| 规则要求 | 实现方法 | 不能越界声称的能力 |
|---|---|---|
| 时序 | 非法/缺失时间、间隔偏差、倒退、帧号缺口/乱序、全局 index 偏移一致性、元数据长度 | 单一 timestamp 不能区分消息生成与记录两套时间；规整不等于真实时钟恢复 |
| 同步 | path/frame_index、逐路覆盖缺口、视觉—本体/跨相机运动时滞、画面停滞 | 无独立硬件时间戳，时钟漂移不可实测；头尾缺图仅提示可能晚启动/早停止 |
| 内容结构 | 文件/schema/shape/dtype；解码、黑白屏、模糊、重复；数值维度、空值、Rotation-6D、突跳、分组残差 | 花屏和遮挡尚无专门正样本评测；工程范围不是已知硬件安全极限 |
| 数据价值 | 空闲率、交互运动代理、视觉 aHash 多样性、全任务分布、全模态冗余 | 不能把运动代理称作任务成功片段，也不能把 aHash 称作语义场景覆盖 |
| 全量报告与治理案例 | 89 条完整清单、逐帧问题、区间、哈希、逐格审计、mask/clip、真实副本复检 | 不把“算法标记”当成官方异常真值 |

state/action 不要求同一时刻相等：先搜索单条轨迹的固定时移，再比较位置/姿态/夹爪分组残差；不允许逐帧自由挑选最有利 lag。它衡量与正常参考的统计一致性，仍不能证明 action 是当前状态、下一帧目标还是控制命令；时移不稳定和残差异常只能触发复核，不能据此复制 state 覆盖 action。

## 4. 哪些能修，怎样修

| 问题 | 自动治理条件与方法 | 保留的风险/不可做的事 |
|---|---|---|
| task/episode/index 错误 | 元数据唯一确定；index 众数唯一且支持 ≥90%，帧号连续；只改错误单元格 | 元数据冲突、50/50 偏移不选边 |
| 类型不符 | 可证明数值不变才转为声明类型，schema 入审计 | 列表 float64 不静默降为 float32 |
| 时间单位/起点 | 连续 frame_index；变换后落在容差内；保留实际变换后的残余抖动 | 抖动/缺失默认不重建；非零起点可能有真实意义，需保留原始时间和来源契约 |
| 时间标称规整 | 用户显式选择 nominal 时按 frame_index/fps 写副本并标记估计 | 不是恢复实测时间，不跨缺帧/乱序补时钟 |
| 相机整体错位 | 完整 path 固定偏移、对端缺口匹配、帧号连续；本臂 r≥0.6 或跨相机 r≥0.8，增益≥0.1且无强矛盾 | 阈值为工程门槛非概率；只移动已有 bytes，缺失端置空；弱场景相关不自动修 |
| 稀疏非有限数值 | 受影响行 ≤10%、连续缺口 ≤2，两侧可信且帧号连续；逐分量插值/Rotation-6D 约束解 | 首尾、长缺口、乱序、不可信邻域拒修；补值仍为估计，不能证明真值 |
| 孤立位置异常 | 极少单帧越界、相邻可信且连续；只对越界分量取邻帧均值 | 连续越界不插值；工程位置界限不当作硬件极限 |
| 元数据 length | 按实际可读行数生成补丁 | 不改写官方 meta 文件，不据此补造缺帧 |
| 黑屏/模糊/损坏图像/缺段 | 保留问题证据与掩膜，提取仍连续可靠的片段 | 不补画面、不靠去噪生成“真实采集”图像 |
| 冗余 | 同一已知任务，全部模态与顺序匹配，相对时间一致，整片段被已保留片段直接覆盖才剔除 | 不用无序集合/传递分组删除独有内容；部分重合保留上下文 |
| 长段数值缺失、整体姿态噪声、本体时移 | 候选方案+人工复核/回采 | 不整段插值、不自动重正交化、不任意平移 state/actions |

相机相关峰稳定性尚未用独立采集批次证明，自动重对齐是“path + 统计证据”的工程假设；有安全要求的部署应增加人工确认或设只检测模式。规则复检不会使这个假设变成硬件真值。

## 5. 分数、掩膜与训练准入

评分权重：结构 25%、时序 20%、同步 20%、内容 20%、价值 15%。每个问题码归属一个维度；同一成因仍可能触发多个码，不宣称已实现因果互斥。文件不可读/处理异常为 0 分；缺字段≤25，整路相机缺失≤40；未验收的视频模态不放行。

修复前后都排除数据集级去重扣分，冗余及剔除数量单列，防止用修复后的决策影响修复前分数。因此新旧版总分不能直接比较。价值部分不可观测时留空，不包装成满分。

分数不是训练开关。准入遵循：复检无阻断码 → 帧号连续且至少 30 帧 → 安全去重 → `train_keep=True`。训练窗口只能在同一 clip 内生成，窗口超过 30 帧应相应提高 `--min-clip`。

- `frame_valid`：最终无阻断码，默认共有 9,863 行。
- `train_keep`：最终合格片段内帧，共 8,881 行。相差的 982 行不满足片段条件，不能散点喂入训练。
- `estimated_repair`：插值/约束补值/标称时间重建的行；涉及这些估计的轨迹默认权重上限 0.5。
- `mask_index.csv`：明确读原文件还是修复副本；保留原文件的 `data/` 路径。
- `load_governed.py`：实际检查来源路径、片段行数、帧号连续、时间递增、掩膜与权重；`python -O` 不关闭校验。
- `governed/` 是叠加层，不是可单独直接加载的完整 LeRobot 数据集。

默认治理策略互斥：25 条整段可用、6 条修复后整段可用、16 条切段使用、2 条部分修复+切段、38 条隔离回采、2 条文件不可用，合计 89。最终未自动剔除重复帧不代表没有图像重合，而是没有满足严格同任务全模态有序覆盖的可剔除片段。

## 7. 检测验证与统计边界

| 验证层 | 协议 | 实测 |
|---|---|---|
| 历史边界回归 | 23 个探针，包含输入覆盖、跨缺口补值、float64 保真、并列偏移和非传递去重 | 23/23 通过 |
| v3.2 安全单测 | 24 个独立边界用例，在普通和 -O 模式分别执行 | 两种模式均 24/24 通过，不重复算成 48 个独立用例 |
| 参考集留一 | 20 折，每折其余 19 条重新标定 | 缺陷误报 0/20，价值提示 0/20 |
| 合成故障 | 底本 ep12、16、0；标定时排除全部底本，用其余 17 条；3×39 用例 | 117/117 满足预设期望；另有 3 个重对齐逐字节检查 |
| 已知注入行的帧级指标 | 按期望问题码与注入行比较 | TP=510、FP=0、FN=6；P=1.0000、R=0.9884、F1=0.9942 |
| 真实全量验收 | 完整 89 条检测，回读全部修复副本，实际加载全部训练片段 | 两策略均通过；115 个输入文件哈希未变；处理异常 0 |

117/117 是“用例满足期望”，含干净对照与低于阈值的负例，不是 117 个真实异常全检出。合成标定的冻结最短阈值为 12 帧，8 帧冻结按预期不报；15/30 帧冻结共漏掉 6 个区间首帧。帧级 P/R 只针对已知注入行与指定问题码，不是 89 条真实数据的 P/R，也不是所有图像问题的召回率。

20 条留一结果不能宣称泛化误报率 0%。仅作样本量提示：若有 20 个独立同分布正常试验且零误报，单侧 95% 二项上界仍为 `1-0.05^(1/20)=13.91%`；当前留一折训练集相互重叠，不满足独立试验条件，**13.91% 也不是本算法已成立的泛化置信区间**。连续帧与同底本注入高度相关，因此不输出把每帧当独立样本的虚窄 F1 区间。

下一阶段需外部独立正常批次、多任务/多采集条件、独立标注异常片段；以 episode/采集批次为重采样单位，报告区间、各故障类型召回与阈值敏感性。下游成功率/碰撞率须固定模型、划分、种子和训练预算做对照，当前不填造提升幅度。

## 8. 数据价值与统一分母

元数据声明 17,360 帧；可读记录 17,213 行（88 条文件可读，另 1 条不可读）；原始帧级问题码命中 6,676/17,213 行。这是对行去重后的命中数，不是问题码条数或图像张数。三路图片按实际解码计数，修复复检再次解码单列为工作量，不用于异常比例分母。

声明任务共 2 个。原始任务可判定的轨迹计数为 42/45，共 87 条；其余任务信息不可判定，不假装补进任一任务。默认最终训练帧按修正后的任务统计为 4,602/4,279；比例 min/max=0.9298，归一化熵=0.9990。此为任务标签均衡，不代表抓取阶段/目标物/环境/视角语义覆盖。

现有 idle_fraction、interaction_rate、visual_diversity 提供低价值与覆盖的代理信号；缺少任务阶段真值，不能直接确认“高价值片段缺失”。当输入是视频编码且尚未解码时明确不可评估并阻断训练，不给假满分。

## 9. 复现、效率与交付边界

在 `03_复赛算子/Raw_data/` 下运行，输出必须是与输入不重叠的新目录：

```bash
python tools/test_safety.py
python -O tools/test_safety.py
python tools/regression_probes.py --reference <参考集> --output <探针专用目录>
python tools/selftest.py --reference <参考集> --output <自测专用目录> --workers 4
python tools/acceptance.py --input <测试集> --reference <参考集> --output <保守策略结果> --workers 4
python tools/acceptance.py --input <测试集> --reference <参考集> --output <标称规整结果> --timestamp-policy nominal --workers 4
python tools/load_governed.py --dataset <测试集> --output <保守策略结果>
```

依赖按算子 requirements 安装。本机验收 Windows 11、Python 3.13.5、AMD Ryzen 7 5800H（16 逻辑线程）、31.86 GiB 内存，4 workers。首轮保守全量日志为 54.74 秒、55,204 次实际解码（含复检），包含 CSV/Parquet 写出但不含最后 summary/xlsx 序列化；同期有其他自测且未分冷/热缓存，**仅作诊断，不用来宣称线性扩展或独立吞吐基准**。完整最终计时以各次 summary.json 为准。

实测库版本：NumPy 2.5.2、PyArrow 25.0.1、Pillow 12.3.0；这里只记录运行环境，不代表 requirements 下所有版本组合都测试过，也未完成 Docker 构建/复赛平台适配验收。

本地产物根：`02_过程数据/08_v32验收/`。

- `full89_conservative/`：默认建议使用的报告、修复副本、掩膜与 61 个片段。

- `report/acceptance.json`：实际验收状态；`validation/v3.2_acceptance.json` 为可入库的非敏感摘要。

## 10. 仍不可消除的边界

真实数据无官方逐帧真值；独立硬件时钟、花屏/遮挡专门检测、语义场景覆盖、任务成功/碰撞等下游收益尚未验证。20 条参考样本不足以证明泛化；工程阈值和位置/夹爪单位应随新任务重新确认。规则复检和合成测试通过只能支持当前明示条件下的交付，不能保证所有未知数据无误或宣称全局最优。
