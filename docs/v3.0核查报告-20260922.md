## 三、必须修复的高优先级问题

### P0-1 输入输出重叠时，原始数据只读承诺不成立

`pipeline.py:102` 直接将修复文件写入 `<output>/governed/data/<rel>`，入口没有检查它与输入文件是否为同一文件，也没有禁止输入/输出目录包含关系。

在新建合成测试中，以 `<sandbox>/governed` 为输入、`<sandbox>` 为输出，补一个 timestamp 缺失值后，输入 Parquet 的 SHA-256 已发生变化。这不是官方原始文件被覆盖，而是防护缺失的可复现反例。

整改：启动前解析绝对路径、软链接及实际写入目标，拒绝任何读写重叠；已有输出目录需隔离运行标识，避免上次修复副本被递归当作下一次输入。写入宜使用新临时文件、校验后原子落盘。

### P1-2 跨轨迹去重会过度剔除

`pipeline.py:135` 仅比较无序图像 hash 集合，重合率分母取较小集合；`report.py:36` 对“重复”关系做并查集传递闭包，然后每组只保留一条。

已构造并跑通报告反例：A 有 100 张图、C 有另 100 张图，两者完全不重合；B 同时包含 A/C，但 B 不可用于训练。A–B、B–C 均被记作 100% 重合，三条被合为一组，最终 A 的 100 帧保留，C 的 100 帧被剔除。仅因桥接关系就删除互不重合的有效内容。

真实数据中 ep42–78 重合率 94.4% 也是按较小图像集合计算，不代表双向整轨等价。图像重合也不能证明 state/actions、任务标签和时序一致。

整改：只把全模态、顺序一致的整轨等价用于自动整轨剔除；包含/部分重合保留非重合片段；每个被剔除片段必须有直接、可用的保留片段覆盖，不能仅靠组内传递关系。

### P1-3 少量合法或损坏输入仍可导致整个批次崩溃

- `features.py:213` 在 5 帧输入、最大 lag=12 时产生不等长切片，实测抛出广播 `ValueError`。
- `_matrix` 遇到 state 列中一个不可解析字符串时，实测抛出 `ValueError`，不是返回问题码。
- `_scalar` 对长度为 2 的列表直接取第一个值，例如 `[1,99]` 被当成 `1`；未报告 shape=1 的结构违规。
- `pipeline.py` 对 worker 的 `future.result()` 没有逐文件异常兜底，一个异常可终止全批次。

整改：lag 上限按有效序列长度裁剪；逐分量解析与 shape 检查；每条轨迹异常转化为失败记录；其余轨迹继续执行。自测应将这些失败作为非零退出状态。

### P1-4 数值修复仍存在不可信邻域和非唯一证据

- `repair.py:203` 实际使用行号比例插值，不是时间比例；不检查中间 frame_index 缺口，也不验证两侧邻居已通过其他质量门禁。
- 合成反例帧号 `[49,150,151]`、位置邻值 `0/0.8`：程序仍补出 `0.400000006`；按该反例实际时间比例约为 `0.792156870`。这种跨大缺口情形首先应拒绝自动补值，而非改用另一插值公式直接放行。
- `detect.py:165` 与 `repair.py:96` 仅取 index 偏移众数，无多数占比和唯一性条件。172 行中两种偏移各 86 行，仍任取一边并改写另 86 行。
- float64 反例中补一个 NaN，还改变了 1 个原本有限分量（约 1.23e-9），审计只记录 NaN。原因是整条被触碰的行强制转 float32。真实 ep80 已解决，不代表任意输入 dtype 下都保证不改有限值。

整改：按字段 dtype 保真、只写目标单元；拒绝跨缺帧、乱序、不可信邻域；偏移需唯一且满足预设支持比例；所有实际改动逐值匹配审计。

### P1-5 33/33 自测结论在完整参考集下不能复现

本次使用 README 命令、完整 20 条参考轨迹，得到 32/33。失败案例 ep929 为右腕非字节重复的视觉停滞。

排除底本后的 19 条标定使 `freeze_min_run` 从随包值 10 升至 15；注入的 15 张冻结画面只有 14 个相邻运动差分满足冻结条件（行 102–115），从而漏检。说明对标定样本与“帧数/差分数”口径存在敏感性。

`selftest.py` 只打印漏检和 `repair=FAIL`，最终进程仍退出 0；错误可能被 CI/平台当作自测成功。另外 33 项包括干净对照，命中期望码不统计额外误报，不能直接当作 Precision/Recall/F1。

整改：统一阈值与区间长度定义；明确提供默认 10 条标定所用 episode ID、输入 hash、阈值 hash；测试多条底本、多种持续长度/强度，统计类别和帧级混淆矩阵；失败必须返回非零状态。

## 四、仍需补充说明或验证的事项

| 项目 | 当前不足 | 建议 |
|---|---|---|
| 同步的可观测性 | 新增覆盖缺口和视觉—本体时滞是实质进展；但缺图分布只能证明头/尾缺数据，不能唯一证明传感器晚启动/早停止。相关峰偏移也不是独立时钟漂移实测 | 分开报告索引偏移、覆盖缺口、统计时滞、真实硬件时间同步，标明不可评估项 |
| 相机自动移位前提 | `repair.py:148` 无 `vk_implied_shift` 也可执行；有该值只看偏移量，不检查相关强度、增益和峰值稳定性；ep74 无腕部内容校验 | 证据不足仅输出候选方案；增加帧号连续性、path 完整性及独立内容证据门禁 |
| 时间戳规整 | 只凭连续 frame_index 就重建整个时钟，可能掩盖真实采样抖动、合法绝对时间或未知起点 | 将时间归一化与真实采样时刻恢复分开，要求明确数据契约，保留原始时间 |
| 位置/夹爪范围 | `position_envelope=1.0`、夹爪 `[-0.05,1.05]` 实为固定 fallback；校准函数没有从参考集估计它们，规则只给布局未给归一化边界 | 不得称已学习的参考包络或已确认硬物理边界；补来源、单位和任务条件 |
| 价值不可评估 | ep2 缺 right_wrist_image，仍显示 value_score=100；只要任一相机可解码就参与完整价值评价 | 分别列运动/各相机/任务覆盖的可评估范围，缺失维度不包装成满分 |
| 任务/场景覆盖 | 任务分布只统计已出现 task，未把声明但缺失的 task 计 0；单任务甚至空统计默认均衡度/熵为 1；aHash 多样性不等于场景覆盖 | 使用完整任务清单和任务阶段；没有语义标注时明确称代理指标 |
| 价值评分与去重 | 重复问题码在 `_pack` 评分后追加，且 `score()` 本身也不扣重复分；可出现重复标签但 value_score=100 | 定义冗余是否影响价值分，并在数据集检测完成后统一计算 |
| 治理元数据 | total_frames 已按实际修复副本更新为 3069，优于旧版；但保留的 ID 为 6、11、13…80，splits 仍写 `0:16` | 标明这是 overlay，不是可直接加载的完整 LeRobot 数据集；提供可靠索引/加载器并测试 |
| 掩膜和片段 | “隔离回采”可能仍有短小 train_keep=True 的散点，但无满足 30 帧要求的 clip | 区分 frame_valid 与 window/clip_eligible；训练端只按约定消费连续片段，补动作窗口和时间连续性检查 |
| 因果重复扣分 | 同一问题码只有一个维度，但黑屏等仍可同时触发内容和视觉多样性；这是多效应，不等于证据因果互斥 | 公开评分含义，做单缺陷评分消融，避免宣称绝对不重复扣分 |
| 覆盖仍有缺口 | 尚无独立硬件时间戳漂移测量、专门的花屏/遮挡正样本评测、任务成功/碰撞率下游验证 | 列出未覆盖项及验证计划，不能把代理检出等同全面覆盖 |
