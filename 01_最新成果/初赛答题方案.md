## 2. 数据范围与语义口径

### 2.1 数据从哪里来、如何分组

本方案只使用组委会提供的初赛数据压缩包。压缩包内已经预先划分“参考集”和“测试集”：参考集 20 条，规则声明为无异常案例；测试集 89 条，作为本次初赛待检测数据。**这 20/89 不是参赛方随机拆分、不是按质量分切分，也不是检测后反向挑选。**算法仅在参考集上建立正常包络和校准阈值，再将冻结后的规则一次性应用于 89 条测试轨迹。

2026-09-02 对重新解压后的数据做了完整性复核：89 个测试集 Parquet 与 3 个 meta 文件经逐文件 SHA-1 校验，与首次分析所用副本字节级完全一致；参考集 20 条为同一正本。因此本报告全部数字在两次独立解压之间可完全复现，不存在因数据变动导致的口径漂移。

LeRobot 元数据中的 `splits.train` 是数据格式内部的 split 字段，不是本方案重新做出的“训练集/测试集”划分，也不改变组委会给定的参考集与测试集角色。

### 2.2 图片从哪里来

三路图像不是从互联网、截图目录或生成模型获得，而是直接嵌入每条 Parquet 记录：`image`、`left_wrist_image`、`right_wrist_image` 均包含二进制图像 payload 和 path 信息，payload 实际为 PNG 数据，标称分辨率为 224×224×3。方案中的黑屏、重复、模糊、清晰对照和三相机案例图，全部由测试集原始 Parquet 的这些字节解码生成；未使用外部图片或生成式图片作为检测证据。

### 2.3 字段语义与分母

题目规则给出三路 224×224×3 图像、20 维 state/actions 及时间和任务索引。20 维拆分按比赛规则解释为两组“3D 位置 + Rotation-6D + 夹爪”，而不是仅依据本地 `info.json` 猜测。与此同时，本地 metadata 的 `robot_type` 为 `panda`，与规则文案中的机器人形态存在口径差异；检测器把 20 维布局做成可配置 schema，提交材料不再据此额外宣称具体机器人硬件形态。

测试集各统计量的分母不同，统一解释如下，避免把“元数据记录、结构可读帧、视觉帧、标记帧”混为一谈：

| 统计量 | 数量 | 含义 |
|---|---:|---|
| 元数据期望记录 | 17,360 | `meta/episodes.jsonl` 汇总的轨迹长度 |
| 结构可读帧 | 17,213 | 88 个可读 Parquet 中实际可扫描的行；episode 82 文件损坏 |
| 三路视觉帧 | 17,009 × 3 = 51,027 张 | episode 2 缺三路图像字段，因此不进入视觉解码 |
| 算法标记帧 | 6,042/17,213，35.10% | 至少命中一个帧级 issue code；不是官方真值异常帧 |
| 连续问题区间 | 509 | 将相邻同类帧级标记聚合后的治理工单区间 |

轨迹级 issue 不一定产生帧级标记，例如“轨迹内 task 切换”可在轨迹汇总层判定，但不把整条轨迹的每一帧都重复标红。因此，需复核轨迹数、标记帧数和问题区间数是三个互补口径，不能互相直接换算。

## 3. 检测与治理流程

```text
Parquet/meta 只读输入
  → 文件与 schema 门禁
  → timestamp/frame/index 时序检查
  → 三路图像路径、覆盖和任务索引同步检查
  → 图像解码/shape/屏幕/清晰度/重复检测
  → 视觉冻结×本体运动跨模态遮挡（v2.2）
  → state/action 有限性、物理约束、最佳时移残差、突跳/低信息检测
  → IsolationForest 无监督补充通道（不计入 61/89）
  → 四类 issue_code + 逐帧 mask + 五维 0–100 评分
  → 可逆项生成修复副本；不可逆项隔离回采
  → SHA-256、repair manifest、quality_mask、同版本复检
```

原始 Parquet 始终只读。修复输出到 `repaired_data/`，每条修复记录源文件与修复文件 SHA-256、修改行数、规则版本和逐行质量 mask，支持审计与回滚。修复 sidecar 中 `quality_mask=False` 表示“该源数据行发生过治理改写、训练使用前应保留审计标识”，不表示修复副本复检失败；是否通过以 `passed_full_recheck` 和 `verification_status` 为准。

## 4. 四类检测方法

### 4.1 时序

- 基于 `Δtimestamp`、`Δframe_index`、`Δindex` 检测重复/倒退、乱序、掉帧、帧率抖动与漂移；
- 正常周期由 fps=10 得到 0.1 s，并用参考集稳健分位数验证；
- 对 `timestamp/frame_index` 比值接近 10、100、1,000 的情况单独标记时间单位不一致，避免误报为大规模掉帧；
- 只有 frame 连续且无倒退时，才允许按 `frame_index/fps` 重建时间戳。

### 4.2 同步

当前文件只有公共 `timestamp`，没有各相机/控制器独立时间戳。因此规则通道能证明的是“索引与覆盖同步”（L1）：图像 path 与 frame 对齐、三路模态覆盖、task_index 合法性和单轨迹任务一致性。

v2.2 进一步做了**负向实验**，而不是停留在“数据条件不满足”的声明：用真实逐帧像素运动（`motion_mad_prev`）与 `state_step_l2` 做 ±6 帧互相关，并额外做去趋势版本。参考集 lag0 命中率 0.00、|lag| 均值 5.25；测试集 lag0 命中率 0.00、|lag| 均值 5.07；去趋势后分布仍然重合。结论：**本数据集在该时间尺度上视觉全局运动与本体运动并不锁定，任何基于此的时滞/漂移判据都会对干净参考集约产生 50% 误报，因此明确不做伪检测器。** 这是可核验的零假设检验，不是借口。

与此同时，跨模态**遮挡**有真实信号：三路相机帧间像素变化≈0 且本体步长处于本轨迹运动分布上四分位，连续 ≥20 帧，编码为 `S_VISUAL_FREEZE_UNDER_MOTION`。参考集 LOEO 0/20，测试集 4/88（ep15/69/85/88，共 126 帧）。这 4 条此前已被 `C_IMAGE_SCREEN/BLUR/DUPLICATE` 标记，故 61/89 不变；变化的是诊断从“暗帧代理”升级为“视野冻结而控制仍在继续”。

生产扩展接口预留：独立 timestamp 到位后增加首尾覆盖差、offset、线性 drift。PPT 中将当前能力明确命名为“同步层 L1：索引/覆盖 + 冻结/运动”，避免把不可测的时钟漂移写成已覆盖。

### 4.3 内容/结构

- 文件/schema：Parquet 可读性、必需字段、行数与 metadata 长度；
- 图像：payload 缺失与解码损坏分开编码，检查 shape、黑屏/过曝/低对比、梯度/Laplacian 清晰度、相邻完全重复；aHash 只作为近重复辅助证据，不作为最终唯一判据；
- 花屏：噪声残差（Laplacian 的 MAD）+ 色度散布联合检验，阈值取参考集各流最大值/p99.9。参考集 0 帧超标，测试集 51,027 张图中仅 1 帧超标（ep76 右腕）。**判定本数据集不含花屏样本，不为花屏单独建规则检测器**；
- 数值：NaN/Inf、位置/夹爪范围、Rotation-6D 两列范数与正交性、state/action 相邻 L2 突跳。

图像 shape 不再为“过 schema”而强制拉伸；黑屏、模糊、重复或大段损坏不使用生成模型伪造内容，而是生成 mask、隔离或回采。

### 4.4 数据价值

v2 将“物理合法性”和“训练价值”拆开。价值侧新增参考集校准的代理指标：低信息帧占比与最长低信息段、state/action 交互运动比例、可用高价值片段比例、三路视觉 aHash 多样性、任务分布与均衡度。

测试集有效任务计数为 task 0：42 条、task 1：45 条，均衡度 `min/max=0.9333`，归一化熵 0.9991；另有 2 条任务索引无效或文件不可读。价值覆盖均分 93.82，4 条高 idle、4 条高价值代理不足、10 条视觉覆盖代理偏低。

上述是训练价值代理，不等同场景真值。数据未提供成功率、碰撞率和场景标签，因此不虚构“治理后任务成功率提升”；下一阶段需将质量分与 imitation learning loss、成功率和碰撞率做相关性/分层实验。

### 4.6 无监督补充通道（IsolationForest）

规则通道负责可解释的确定性判定；学习通道只负责未见模式的补充召回，**不替代 61/89**。实现：在参考集轨迹级特征（时序/图像/数值 + v2.2 的 motion/noise/chroma）上训练 IsolationForest，阈值取 20 条参考集 LOEO 异常分的最大值，从而参考集观测误报为 0/20。测试集 27 条超过该阈值，其中 25 条已在规则 61 内，另 2 条（ep5、ep57）仅作为补充复核名单写入 `outputs/unsupervised_iforest.csv`，不进入 issue_codes。

## 5. state/action 语义与对齐修正

不再直接假设 `state_t≈action_t`。对每条轨迹搜索 `lag∈{-1,0,+1}`，分别比较 action 与对应时刻 state，选择 RMSE 最低的对齐作为残差证据；只有最佳对齐后的 RMSE>0.15 或最大分量>0.40 才标记不一致。报告同时输出最佳 lag，便于判断 action 是当前目标、下一帧目标还是延迟记录。

该方法仍不替代官方控制语义字典。如果官方定义 action 为速度、增量或不同坐标系目标，应关闭绝对残差规则，仅保留有限性、范围、突跳和任务阶段条件基线。

## 6. 去重评分与门禁

总分为：

`Q = 0.25·结构 + 0.20·时序 + 0.20·同步 + 0.20·内容 + 0.15·价值`

权重设定依据：结构是文件级可用性的前提（且承担硬门禁），权重最高；时序/同步/内容是赛题明确定义的三类核心缺陷，等权；数据价值为无真值条件下的代理指标，权重最低。该权重只影响 0–100 分的排序口径，不影响 issue code 的检出与定位。

五维证据互斥归属：schema/长度只扣结构；timestamp/frame 只扣时序；path/覆盖/task 只扣同步；图像逐帧质量只扣内容；训练价值代理与最佳时移数值残差只扣价值。文件级状态另执行硬门禁：核心 Parquet 损坏记 0 分，必需模态/字段不可读最高 25 分。这样避免同一缺陷跨维重复处罚。

逐帧 blur、shape、屏幕、重复、数值异常均汇总到轨迹级对应维度；轨迹报告、逐帧报告和问题区间使用同一 issue_code 口径。

### 6.1 权重敏感性

对每维权重 ±0.05 并补充等权情景，共 11 种权重组合重算总分（`outputs/weight_sensitivity.csv`）：

- 轨迹排名 Spearman 相关系数最低 0.983、均值 0.995——**排名结论对权重选择高度稳健**；
- <85 分标记集合 Jaccard 最低 0.714——标记主体稳定，边界样本有少量进出；
- 最差 10 条成员 Jaccard 最低 0.538——垫底名单对权重较敏感，因此报告同时保留五维分，不只依赖总分做取舍。

### 6.2 标记置信度分层

61 条需复核轨迹按 issue code 的证据强度分三级（轨迹取最高级，`outputs/confidence_summary.json`）：

| 级别 | 轨迹数 | 占比 | 判据 |
|---|---:|---:|---|
| 确定性 | 43 | 70.5% | 文件损坏、schema 缺失、NaN/Inf、时间戳倒退、索引乱序、task 非法、相邻字节级重复等事实判定，不依赖统计阈值 |
| 高置信 | 10 | 16.4% | 黑屏/过曝像素统计、物理范围/Rotation-6D 违规、path-frame 不一致、payload 缺失等强证据 |
| 阈值型需复核 | 8 | 13.1% | 模糊、抖动、突跳、state-action 残差、低信息代理等参考集校准阈值判定，边界样本建议优先人工复核 |

置信度只描述证据强度，不改变质量分。它回答“68.54% 标记率是否过高”的质疑：其中 70.5% 是与阈值无关的事实性缺陷，统计阈值判定的仅占 13.1%。

## 7. 独立验证与置信边界

### 7.1 参考集留一验证

对 20 条 clean reference 做 LOEO：每轮用 19 条校准阈值，检测剩余 1 条。结果 0/20 被标记，故可报告“参考集留一观测误报率 0%”；这比用同一批数据校准并回测更严格，但样本仍小。按零事件二项分布上界 `1-0.05^(1/20)` 计算，真实误报率的单侧 95% 上界仍约为 13.9%，因此不能据此宣称所有正常场景均零误报。

### 7.2 合成异常压力测试

在 clean reference 副本上确定性注入 20 条异常轨迹，覆盖 20 种故障：时序 jitter/rollback/drift/duplicate/gap，同步 task invalid/switch/path mismatch/stream offset/episode mismatch，内容 black/bright/shape/duplicate/corrupt payload，价值 NaN/位置突跳/Rotation-6D 非法/夹爪越界/action jump；另保留 20 条 clean 对照。

整体轨迹级 P/R/F1 均为 1.000，逐帧级均为 1.000。分类型中同步类 Precision=0.833、Recall=1.000、F1=0.909，暴露出覆盖同步规则仍可能把部分参考边界样本标记为同步问题。完美总体指标仅说明这些明确注入故障被稳定恢复，不作为隐藏测试集指标。

### 9.2 批处理扩展

瓶颈仍在图像解码（单进程约 94%），轨迹之间无共享状态：

- **并行单元**：以 episode 为最小任务片，worker 独立解码并落盘逐帧特征，主进程只做追加归并；
- **实测而非目标**：16 worker 将全量图像扫描从约 137 s 降至 33.09 s（4.34×）。该数字来自本机，复赛平台需用固定硬件复测；
- **分布式扩展**：任务片无状态，可映射到 Spark/Ray 或平台算子；图像特征落盘格式与单进程一致；

### 10.1 场景价值与落地路径

RefSync-QA 的价值不是把所有异常“自动改好”，而是在机器人训练数据进入模型前建立可审计的质量门禁，把人工从无差别逐帧浏览转为按证据强度和连续区间处理：89 条轨迹输出 61 条明确处置指令，6,042 个帧级标记聚合为 509 个连续工单区间，同时保留 28 条无需处理轨迹，降低人工检索和误删正常数据的成本。

落地可分为三层：

1. **采集入库门禁**：上传 Parquet/meta 后自动完成 schema、时序、同步 L1、图像和数值检查；核心文件损坏或必需模态缺失执行硬门禁；
2. **数据发布治理**：生成轨迹评分卡、逐帧 mask、区间工单和治理动作；证据唯一的可逆问题输出新副本，其余进入隔离、回采或训练降权队列；
3. **训练闭环验证**：当平台提供任务成功率、碰撞率、loss 和场景标签后，按质量分分层训练，验证“质量分—训练收益”相关性，再学习或校准评分权重。

工程形态已预留为参数化 CLI（`src/run_pipeline.py`），输入为数据集目录，输出为 xlsx/CSV/Parquet mask、修复副本和审计 manifest。当前单机全量图像扫描 16 进程 33.09 秒（单进程基线 137 秒），适合离线批处理。若在芜湖机器人企业、数据平台或科创载体开展试点，可先以“采集批次质量验收 + 回采工单”为切入点，再扩展到训练效果关联评估；该表述是合作路径建议，不代表已有落地合同或下游提升实测。

仍需平台或官方数据支持：

1. 测试集人工/官方标签，用于真实 Precision、Recall、F1 和 PR 曲线；
2. 各传感器独立 timestamp，用于真实 offset/drift/早启晚停测量（当前互相关实验已证明像素全局运动不能替代该字段）；
3. 场景、成功率和碰撞率，用于验证质量分与下游训练收益；
4. 更大正常集与不同采集批次，用于阈值稳定性和域外误报评估。

提交合规方面，官方参赛表、团队名称、成员与联系方式仍需参赛者本人补齐；最终 ZIP 应严格命名为 `赛题名称-团队名称-作品名称.zip`，至少包含参赛表和 PPT，且小于 200MB。全量 xlsx、技术说明和轻量审计附件可一并放入 ZIP；324.54 MiB 的修复 Parquet 应上传网盘并在文档中写明链接、提取码与 SHA-256。

| 评委问题 | 统一回答 |
|---|---|
| 20 条参考集和 89 条测试集是怎么分出来的？ | 由组委会数据包预先分目录提供，不是随机拆分或检测后选集。参考集按规则作为无异常案例校准，冻结规则后对 89 条测试集做全量检测。 |
| 图片从哪里来？ | 图片是 Parquet 每行内嵌的三路 PNG payload；所有案例图由原始字节解码，没有使用网络图片或生成图作为检测证据。 |
| 61/89 是真实异常数量吗？ | 不是。它是算法标记的需复核轨迹；规则只说明测试集整体含异常，没有给出逐轨迹/逐帧标签。43/10/8 的置信度分层用于区分事实判定、强证据和阈值型标记。 |
| 参考集 0% 误报是否过拟合？ | 已使用 LOEO，每轮只用 19 条校准、1 条验证，避免同集回测；但 0/20 的单侧 95% 误报率上界仍约 13.9%，因此不宣称域外零误报。 |
| 为什么可以比较 state 和 action？ | 20 维布局依据比赛规则，但不直接假设同帧相等；搜索 lag∈{-1,0,+1} 后只把最佳对齐残差作为辅助证据。若官方定义为速度/增量或不同坐标系，应关闭绝对残差规则。 |
| 没有独立相机时间戳，如何检测同步？ | 规则通道只报告同步 L1：path-frame、三路 payload 覆盖和 task 一致性。v2.2 用像素运动互相关做了零假设检验：参考集与测试集 lag0 命中率均为 0.00，分布重合，因此明确**不做**伪漂移检测器。遮挡改用“视觉冻结而本体在动”的跨模态判据，4 条命中均已在 61 内。 |
| 方案里有没有人工智能算法？ | 主体仍是规则 + 参考集校准。v2.2 增加 IsolationForest 无监督通道，阈值在参考集 LOEO 上取最大异常分（0/20）。测试集 27 条超阈，25 条已在规则 61 内，ep5/ep57 仅作补充复核，不计入 61/89。 |
