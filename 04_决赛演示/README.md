# 04_决赛演示 · RefSync-QA 算法实时演示

演示流程：**① 导入数据 → ② 检测 → ③ 修复 → ④ 对比**。
第 1 步选一份数据——示例数据整批、其中任意一条，或自己的文件 / 文件夹；后三步只处理这份数据。
现场真跑 v3.2.2 算子，所有数字来自这次运行写出的文件；不联网、无外部 CDN；不使用真值标签。

## 依赖

- Python 3.9+，`numpy` / `pyarrow` / `pillow`（算子自身依赖，见 `03_复赛算子/Raw_data/requirements.txt`）
- 仅用标准库起 HTTP 服务，无需 Flask/Django

```bash
cd <仓库根目录>
python3 -m venv .venv
.venv/bin/pip install -r 03_复赛算子/Raw_data/requirements.txt
```

## 启动

```bash
cd 04_决赛演示 && ../.venv/bin/python server.py --port 8765
# 浏览器打开 http://127.0.0.1:8765/
```

macOS 也可双击 `start_demo.command`（自动选可用 Python、清理端口）。

## 四步

| 步骤 | 页面上看到什么 | 操作 |
|---|---|---|
| **1 导入数据** | **示例数据**：「全部 89 条」，或在 89 个编号里点一条（编号下的色条是上次检测状态，紫点表示上次有修复）。**我的数据**：选择文件夹 / 选择文件、拖入、粘贴路径。**历史结果**：之前跑过的数据，点开直接看结果。底部显示已选数据。 | 「开始检测」或回车 |
| **2 检测** | 现场运行算子（只检测）。批量：计时、逐帧检测全景、逐条发现；跑完给结论、用时、需复核数、逐帧定位、问题区间，「需复核清单」按证据强弱排序、可按类别筛选。单条：三路画面 + 游标、问题区间、一句话问题说明。 | 「下一步：修复」 |
| **3 修复** | 同一份数据跑完整算子（检测 → 修复 → 回读核验 → 复检 → 切段）。批量：可训练帧三档（不修不切 / 只切段 / 切段 + 修复）、修复 / 改写 / 拒修数、逐帧去向、每条轨迹的去向、拒修原因。单条：修了还是没修、修复前后同一行画面、可训练帧（和不修复时对比）。 | 「下一步：对比」 |
| **4 对比** | 批量：全量对比（需复核、通过、问题帧、可训练帧的前后变化，两张逐帧全景并排，有变化的轨迹），左侧逐条看：同一现象一修一不修、已修复、拒修示例、修复规则。单条：这一条的修复前后。页面底部三个导出：**可用数据包**、**质检报告**、**复核清单**。 | 点左侧列表 / 导出 |

- 选一条就只看这一条，选一个文件夹就看这个文件夹里的全部轨迹；全景行数、清单、对比都按这份数据生成。
- 顶栏右侧常驻：当前数据 + 结果来源（**现场运行 / 回放 / 历史结果** · 时间 · 算子版本）。
- 颜色：蓝 时序、橙 同步、品红 内容结构、黄 数据价值；绿色只表示"进入训练"，紫色表示"修复后进入训练"。
- `←` `→` 切换步骤，`1`–`4` 直达，`Esc` 关闭弹层，`T` 明暗，`F` 全屏。窄窗口下顶栏自动换两行。

## 建议演示节奏（约 2.5 分钟）

决赛每队 15 分钟：讲解 PPT 和演示作品合计 10 分钟，答疑 5 分钟，不可超时。演示按 2.5 分钟准备。
答辩用 Mac（Apple 芯片 10 核，8 进程，v3.2.2）实测：整批检测 20.1 秒，检测 + 修复 23.5 秒。

1. **导入数据 5 秒**：点「全部 89 条」→「开始检测」。
2. **检测约 30 秒**（运行 20 秒，边跑边讲）："每查完一条，它那一行就铺开，颜色是问题落在哪几帧。"跑完：68 / 89 条需复核、7,730 帧逐帧定位、1,161 段问题区间。
3. **修复约 35 秒**（进入后自动开始，运行约 24 秒，期间讲门控规则）：**可训练 7,916 帧：切段多保留 2,524 帧，修复再增加 975 帧**（4,417 → 6,941 → 7,916）。
4. **对比约 60 秒**：需复核 68 → 62、问题帧 7,730 → 7,209、可训练帧 6,941 → 7,916；点 ep29（r=0.90，修了）和 ep74（r=0.14，没修）；最后指三个导出。
5. **现场点一条**放到答疑：请评委在第 1 步任意点一个编号，单条几秒出结果。

## 答辩前准备

- **在答辩用的电脑上把「全部 89 条」的检测和修复各跑一遍**：第 1 步编号色条、「历史结果」和失败时的「回放上次运行」都取同一份数据最近一次的结果，跑完就是这台电脑、这个算子版本的记录。
- 运行记录里的路径换了电脑或挂载点也能找回（按演示目录上一级的公共后缀映射），所以在别的机器上跑的结果拷过来同样能打开；但硬件和耗时显示的是当时那台机器。
- 旧版本的结果放进 `runs/` 下的归档文件夹（例如 `_v3.2.1_归档_1030`），不会再被当成最新结果。

## 现场口径

- **对比口径**：修复前 = 原始数据的检测结果；修复后 = 修复副本用同一套规则重新检测。不使用任何人工标注。
- **需复核 ≠ 确认缺陷**：它是按证据等级给出的标记，供人复核。
- **可训练帧** = 复检无阻断问题、且连续 ≥ 30 帧。三档都是真跑出来的：不修不切 4,417、只切段 6,941 取自同一份数据的"只检测"运行，切段 + 修复 7,916 取自修复运行。
  基线不用修复运行里的"原本可用"：那里 ep60（232 帧，本来就整段可用）只打了元数据补丁，会被记成"修复恢复"。
- **质量分 ≠ 可训练帧**：质量分是五维加权评分；可训练帧看的是阻断问题和连续长度。ep09 质量分 80，但三路画面都欠曝（平均亮度约 50，参考集下界 60–73），208 帧全部被标记，所以 0 帧可训练。
- **不可修复的问题**：黑屏、模糊、马赛克、噪声 / 花屏、过曝欠曝不能凭空生成画面，不修；被标记的帧不进入训练（ep15 黑屏、ep08 马赛克、ep22 / ep32 花屏、ep45 过曝，都是 0 帧）。
- **红蓝通道互换**（ep46）：整路判定，可以换回来，但不能确定原始通道顺序，所以只写进候选修复，不自动改。
- **拒修不是失败**：证据不足就不动。ep74 path 偏移 +3，但画面内容相关只有 0.14。
- **算子版本**：v3.2.2。比复赛提交的 v3.2 多四项画面检测：马赛克（v3.2.1）、噪声 / 花屏、曝光、色彩通道（v3.2.2，阈值由 20 条参考集逐路标定）。v3.2.2 相对 v3.2.1 只改变 6 条：ep22、ep32、ep45、ep46 从整段可用变成 0 帧（共 800 帧），ep09、ep35 多一个曝光问题码（本来就是 0 帧）。详见算子目录 `CHANGELOG_v3.2.2.md`。

## 导入数据的细节

- **单个文件**：若它在 LeRobot 数据集的 `data/chunk-xxx/` 下，会自动读同一数据集的 `meta/`；单独拿出来的文件没有 `meta/`，元数据相关检查记为不可评估，其余照常。
- **文件夹**：LeRobot 数据集根目录，或只放 Parquet 的普通文件夹；里面有多个数据集时页面会列出来让你选。
- **拖放**：拖进来的文件先复制到 `runs/imports/uploads/` 再测；选择框或粘贴路径直接读原位置。
- **结果位置**：每次运行一个目录 `runs/imports/<编号>/out/`；同一份数据的检测、修复各保留最近 3 次，更早的自动清掉。
- 同一时间只跑一个运行。

## 运行失败与回放

- 现场运行失败时，页面写出失败原因；这份数据以前跑过的话，可以一键「回放上次运行」（按原始节奏重放），顶栏标为"回放"。
- **演示前在这台电脑上把示例数据整批、以及打算现场点的几条各跑一遍**，回放记录和硬件信息就是这台机器的。

## 页面文字自检

页面上自动生成的每一句结论都由 `web/logic.js` 写出；`tools/check_text.js` 用真实运行结果逐条核对文字和算子输出是否一致：

```bash
python3 server.py --no-browser &    # 先启动服务
node tools/check_text.js            # 核对全部运行记录
```

## 配置

`demo_config.json`（相对本目录；可用环境变量覆盖）：

| 字段 | 环境变量 | 说明 |
|---|---|---|
| `operator_dir` | `RSQA_DEMO_OPERATOR` | 算子目录，默认 `../03_复赛算子/Raw_data` |
| `input_dir` | `RSQA_DEMO_INPUT` | 示例数据（赛题测试集）目录，不入库，需本地放置 |
| `runs_dir` | `RSQA_DEMO_RUNS` | 运行记录目录，默认 `runs` |
| `compare_pair` | — | 批量对比里"一修一不修"优先取的两条轨迹，默认 ep29 / ep74 |
| `dataset_label` | — | 示例数据显示名 |
| `port` | — | 默认 8765 |

`input_dir` 默认指向 `../具身智能多模态数据质量检测算法赛题-初赛数据/初赛数据/测试集`，该目录被 `.gitignore` 排除（赛题数据版权归组委会）。

## 接口

见 `server.py` 文件头。页面流程用到：`/api/info`（示例数据）、`/api/import/inspect`、`/api/import/run`（每次检测 / 修复一条运行记录）、
`/api/job`、`/api/result`（修复运行会自动配对同一份数据的只检测运行）、`/api/episode`、`/api/sessions`（历史结果）、`/api/export`。
