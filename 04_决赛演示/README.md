# 04_决赛演示 · RefSync-QA 算法实时演示

演示流程：**① 检测 → ② 修复 → ③ 对比 → ④ 导入测试**。
前三步在赛题公开测试集上跑完整链路，重点看检测过程、修复过程和修复前后对比；第四步用评委指定的数据现场再走一遍。
现场真跑 v3.2.1 算子，所有数字来自这次运行写出的文件；不联网、无外部 CDN；不需要也不展示任何依赖真值标签的指标。

## 依赖

- Python 3.9+，`numpy` / `pyarrow` / `pillow`（算子自身依赖，见 `03_复赛算子/Raw_data/requirements.txt`）
- 仅用标准库起 HTTP 服务，无需 Flask/Django

```bash
cd <仓库根目录>
python3 -m venv .venv
.venv/bin/pip install -r 03_复赛算子/Raw_data/requirements.txt
```

## 启动

```bash
cd 04_决赛演示 && ../.venv/bin/python server.py --port 8765
# 浏览器打开 http://127.0.0.1:8765/
```

macOS 也可双击 `start_demo.command`（自动选可用 Python、清理端口）。

## 四步

| 步骤 | 页面上看到什么 | 操作 |
|---|---|---|
| **1 检测** | 现场调用 v3.2.1 算子（`--no-repair`，只读）。左边大字计时、阶段耗时、四类检测器命中；右边**逐帧检测全景**：每查完一条轨迹，它那一行就按帧铺开，颜色是问题类别；旁边**逐条发现流**一句话写清查出了什么、标记了多少行。跑完给结论、KPI（含各阶段耗时）、帧级全景、四类问题覆盖、报告文件。 | 空格或「开始检测」 |
| **2 修复** | 调用完整算子（检测 → 修复 → 回读核验 → 复检 → 切段）。**逐帧修复全景**里紫色 = 这一行被修复改写，彩色 = 复检后仍有问题；**逐条修复流**标出 修复 / 拒修 / 保持；实时计数 问题行 修复前 → 复检后、需复核轨迹 修复前 → 复检后、四类问题各自 修复前 → 复检后。跑完首屏是可训练帧三档对比（不修 / 只检测+切段 / 检测+修复+切段）和三项复检前后数字。 | 空格或「开始修复」 |
| **3 对比** | 默认打开**全量对比**：五组 修复前 → 修复后（需复核轨迹、通过轨迹、带问题码的帧、平均质量分、可训练帧）、两张逐帧全景并排（左原始检测、右修复副本复检）、四类问题、问题码变化、有变化的轨迹。然后**逐条看**：ep29 修复前后同一行画面并排 + 互相关峰值 +5 → 0；ep74 同样"疑似错位"但 r=0.14，不修。「修复说明」集中写每类问题怎么修、什么条件下才修。 | 点左侧列表 |
| **4 导入测试** | 用自己的数据再走一遍：单个 Parquet、文件夹批量、拖入或粘贴路径；可选「检测 + 修复」或「只检测」。运行时是和第 1、2 步同一个实时面板；跑完单条给叙事页（哪里有问题 → 修没修 → 还剩多少帧能训练），批量给全量对比 + 每条一句话，点开直接看修复前后。 | 选数据 → 开始测试（约 2 秒/条） |

`←` `→` 切换步骤，`1`–`4` 直达，`Esc` 关闭弹层，`T` 明暗，`F` 全屏。产物文件都能点开预览。

## 页面上不出现什么

没有真值标签，所以**任何需要标签才能算的结果都不出现**：准确率、召回率、误报率、复赛成绩单、平台对照数据都已从页面、配置和接口里删除。
页面上所有"对比"都是 **修复前检测 vs 修复后复检**：同一套检测规则对原数据和修复副本各跑一次，数字全部来自算子这次写出的报告。

## 建议演示节奏（约 4 分钟）

1. **第 1 步 50 秒**：按空格。指全景："每查完一条，它那一行就铺开，颜色就是问题落在哪几帧。"右侧发现流逐条出现，例如「左腕相机画面整体错位 +5 帧」。跑完指 64 / 89 需复核、6,910 行逐帧定位、1,149 段问题区间。
2. **第 2 步 60 秒**：按空格。紫色行就是被修复改写的行；指实时变化的「同步问题行 1,011 → 505」和「问题行 修复前 → 复检后」。拒修项会写明原因。跑完停在首屏：不修 4,985 → 只检测+切段 7,741 → 检测+修复+切段 8,716 帧。
3. **第 3 步 90 秒**：全量对比页先讲三组数：需复核 64 → 58，带问题码的帧 6,910 → 6,389，可训练帧 4,985 → 8,716；再看左右全景里的紫色行和问题码表（S_STREAM_SHIFTED 3 → 1 条）。点「逐条看」：ep29 同一行画面修复前第 124 帧、修复后第 119 帧，峰值 +5 → 0；点 ep74：相关度 0.14 < 0.80，没修。
4. **第 4 步 40–60 秒**：请评委指一条数据或一个文件夹，开始测试，约 2 秒一条，结果页和前三步同一套展示。

## 现场口径

- **对比口径**：修复前 = 原始数据的检测结果；修复后 = 修复副本用同一套规则重新检测（复检）。不需要、也没有使用任何人工标注。
- **需复核 ≠ 确认缺陷**：它是算法按证据等级给出的标记，供人复核。
- **可训练帧** = 连续 ≥ 30 帧、复检后不含阻断问题的片段。4,985 → 8,716 里，+2,756 来自切段（只检测也能得到），+975 来自修复（7,741 → 8,716）。
- **不可修复的问题**：黑屏、模糊、马赛克等不能凭空生成画面，不修；被标记的帧直接不进入训练（例如 ep15 全程黑屏、ep08 全程马赛克，都是 0 帧）。
- **算子版本**：演示用 v3.2.1，比复赛提交的 v3.2 多一条马赛克检测（`C_IMAGE_MOSAIC`），89 条里只改变了 ep08（165 → 0 帧）和 ep35（原本就是 0 帧）；详见算子目录 `CHANGELOG_v3.2.1.md`。
- **拒修不是失败**：证据不足就不动，例如 ep74 path 偏移 +3，但画面内容相关只有 0.14，强行移回就是按没有证据的偏移改画面。

## 修复对比里可看的例子

| 轨迹 | 问题 | 修法 | 修复前 → 复检 |
|---|---|---|---|
| ep29 | 左腕相机整体错位 +5 帧 | 跨相机强相关 r=0.90，path 回移 5 帧，开头 5 帧显式置空 | 80.00 → 98.95，可训练 185 帧 |
| ep48 | 右腕相机整体错位 +10 帧 | 本臂运动相关 r=0.91，回移 10 帧 | 80.00 → 97.42，可训练 145 帧 |
| ep80 | state 稀疏 NaN（12 格） | Rotation-6D 按正交约束解出，其余格逐位不变 | 97.91 → 100.00 |
| ep54 | 末端位置孤立单帧越界 | 只改越界分量，取前后帧均值 | 99.63 → 100.00 |
| ep06 / ep11 / ep72 | 任务标签与元数据不一致 | 按 episodes.jsonl 统一，只改 task_index | 80 / 90 → 100 |
| ep74 | 同为 +3 偏移，但跨相机相关仅 0.14 | **拒修**，保持隔离并写入候选 | 80.00（不变），0 帧进入训练 |
| ep08 | 三路相机全程马赛克（约 14×14 色块放大） | 不可修复；v3.2.1 新增 `C_IMAGE_MOSAIC`，256 帧全部标出 | 隔离回采，0 帧进入训练 |

## 第 4 步：导入测试的细节

- **单个文件**：选 `episode_xxxxxx.parquet`。若它在 LeRobot 数据集的 `data/chunk-xxx/` 下，会自动读同一数据集的 `meta/` 做元数据一致性检查；单独拿出来的文件没有 `meta/`，这类检查记为不可评估，其余检测照常。
- **文件夹**：LeRobot 数据集根目录，或只放 Parquet 的普通文件夹；有多个数据集时页面会列出来让你选。
- **拖放**：拖进来的文件先复制到 `runs/imports/uploads/` 再测；选择框或粘贴路径直接读原位置。
- **结果位置**：`runs/imports/<测试编号>/out/`；原始数据只读。
- 同一时间只跑一个测试（第 1、2 步的运行也算）。

## 实时运行与回放

- 右上角「实时运行」：现场真跑算子。「回放」：按原始时间节奏重放上一次实测记录，页面会注明是回放。
- 实时运行失败时，上一次成功的结果不会被覆盖，页面提示改用回放。
- 第 1、2 步右侧「查看上次结果」直接打开最近一次输出。
- 旧版运行器录的回放记录也能用：缺少的逐行数据由服务端从报告补齐。**换机器或改版后，建议在演示用的电脑上实时各跑一遍检测和修复**，回放记录和硬件信息就会换成这台机器的。

## 页面文字自检

页面上每一句自动生成的结论（单条导入页、批量页、实时流水、第 3 步逐条对比）都由 `web/logic.js` 里的函数写出。
`tools/check_text.js` 用真实运行结果逐条核对这些文字和算子输出是否一致，改了页面文字或换了算子版本后跑一遍：

```bash
python3 server.py --no-browser &          # 先启动服务
node tools/check_text.js                  # 核对第 1、2 步的全部轨迹
node tools/check_text.js --imports        # 连同导入测试记录一起核对
```

核对内容：有阻断问题时不能说"没有检测到问题 / 全部帧进入训练"；"全部 N 帧 / 0 帧 / X 帧不进入训练"和
`train_frames`、`quality_masks` 逐帧一致；"被标记的帧不进入训练"时这些帧确实 `train_keep=False`；相机错位修复的置空行数、
门槛证据、分数、改写格数与 `repair_manifest` / `repair_audit` 一致；修了一部分时没修的部分必须写出来；回放流水标签与最终报告一致；
全量对比的每个数字独立重算。全部一致输出 `✓ 全部一致`，否则逐条列出并以非 0 退出。

## 配置

`demo_config.json`（相对本目录；可用环境变量覆盖）：

| 字段 | 环境变量 | 说明 |
|---|---|---|
| `operator_dir` | `RSQA_DEMO_OPERATOR` | 算子目录，默认 `../03_复赛算子/Raw_data` |
| `input_dir` | `RSQA_DEMO_INPUT` | 赛题测试集目录（不入库，需本地放置） |
| `runs_dir` | `RSQA_DEMO_RUNS` | 运行与回放记录目录，默认 `runs` |
| `compare_pair` | — | 第 3 步"同一现象，一个修一个不修"固定的两条轨迹，默认 ep29 / ep74 |
| `port` | — | 默认 8765 |

`input_dir` 默认指向 `../具身智能多模态数据质量检测算法赛题-初赛数据/初赛数据/测试集`，
该目录被 `.gitignore` 排除（赛题数据版权归组委会），需自行从赛事方获取后放到该位置。
`runs/` 不入库（含修复副本 Parquet）。首次使用请先在本机实跑一次检测与修复，回放记录与硬件信息才会生成为本机数据。
