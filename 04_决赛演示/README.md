# 04_决赛演示 · RefSync-QA 算法实时演示系统

现场演示用：在本机真实调用 v3.2 算子，跑完即出结果，所有数字来自这次运行写出的文件。
不联网、不依赖外部 CDN，页面与算法都在本地。

## 与"汇报看板"的区别

| 演示 | 入口 | 形态 | 状态 |
|---|---|---|---|
| **算法实时演示（本目录）** | `start_demo.command` → `http://127.0.0.1:8765/` | 现场跑算子，逐条轨迹点亮、计时、产物可点开预览 | **当前主线** |
| 决赛汇报静态看板 | `_archive_report_demo/index.html` | 纯前端单文件看板，数据为本地全量复现结果 | 已归档，不再维护 |

两套界面的数字口径不同（平台数据 vs 本机赛题公开测试集），**不可混用**，详见文末「口径」。

## 依赖

- Python 3.9+，`numpy` / `pyarrow` / `pillow`（算子自身依赖，见 `03_复赛算子/Raw_data/requirements.txt`）
- 仅用标准库起 HTTP 服务，无需 Flask/Django

```bash
cd <仓库根目录>
python3 -m venv .venv
.venv/bin/pip install -r 03_复赛算子/Raw_data/requirements.txt
```

## 启动

1. 双击 `start_demo.command`（如 macOS 提示"无法打开"，右键 → 打开）。
   也可在终端执行：
   ```bash
   cd 04_决赛演示 && ../.venv/bin/python server.py --port 8765
   ```
2. 浏览器访问 `http://127.0.0.1:8765/`。
3. 全屏 `F`；明暗主题 `T`（投影现场偏亮用亮色，偏暗用暗色）。
4. 关掉终端窗口即停止服务。

## 页面与按键

| 步骤 | 内容 | 操作 |
|---|---|---|
| 1 数据与成绩 | 三路相机实拍画面、数据规模、复赛成绩单、平台实跑耗时 | 点「开始质量检测」或按空格 |
| 2 质量检测 | 现场调用 v3.2 算子（`--no-repair`）：计时、89 条轨迹逐条点亮、四类问题实时累计；跑完显示耗时、需复核数、帧级定位、问题区间、帧级全景图、五维评分、生成的报告文件 | 空格开始；点全景图任一行看单条轨迹 |
| 3 安全治理 | 现场调用完整算子（检测→修复→回读核验→复检→切段）：修复副本实时出现；跑完显示三种处理方式的可训练帧对比、决策流向、拒修理由、治理叠加层文件 | 空格开始 |
| 4 修复前后 | 「修复说明」：每类问题怎么修、必须满足什么条件；逐条修复说明；拒修项目及原因；候选方案。点任一条的「看对比」进入修复前后数据（ep29/ep48 相机重对齐、ep80 NaN 约束补值、ep54 越界、ep06/11/72 任务标签、ep25 类型转换、ep60 元数据补丁、ep74 拒修） | 点左侧列表或「看对比」 |
| 5 导入测试 | 现场导入数据：「选择单个文件」逐条测，「选择文件夹」批量测；也可拖入或粘贴路径。可选「检测 + 修复」或「只检测」；单个文件可直接看画面与修复前后；所有测试进入「测试记录」可回看 | 选数据 → 开始测试 |

`←` `→` 切换步骤，`1`–`5` 直达，`Esc` 关闭弹层。产物列表里的文件可点开预览，「打开输出目录」会在访达里定位真实输出。

## 实时运行与回放

- 右上角「实时运行」：现场真跑算子，所有数字来自这次运行写出的文件。
- 「回放」：按原始时间节奏重放 `runs/<stage>/demo_events.jsonl` 记录的事件流。
- 实时运行失败时，上一次成功的结果不会被覆盖，页面提示改用回放。
- **`runs/` 不入库**（含修复副本 Parquet，体积与数据版权原因）。首次使用请先在本机实跑一次检测与治理，回放记录与硬件信息将自动生成为本机数据。

## 配置

`demo_config.json`（相对本目录；也可用环境变量覆盖）：

| 字段 | 环境变量 | 说明 |
|---|---|---|
| `operator_dir` | `RSQA_DEMO_OPERATOR` | 算子目录，默认 `../03_复赛算子/Raw_data` |
| `input_dir` | `RSQA_DEMO_INPUT` | 赛题测试集目录（不入库，需本地放置） |
| `runs_dir` | `RSQA_DEMO_RUNS` | 运行与回放记录目录，默认 `runs` |
| `platform_summary` | `RSQA_DEMO_PLATFORM` | 平台复赛 summary.json（可选，缺失时页面不显示平台数据） |
| `port` | — | 默认 8765 |
| `official` | — | 复赛成绩单数值（页面第 1 步展示） |

`input_dir` 默认指向 `../具身智能多模态数据质量检测算法赛题-初赛数据/初赛数据/测试集`，
该目录被 `.gitignore` 排除（赛题数据版权归组委会），需自行从赛事方获取后放到该位置。

## 答辩口径

- **两份数据**：现场跑的是赛题公开测试集（本机，89 条 / 17,213 行）；复赛成绩与 49.12 s 是大衍平台上的复赛数据集（89 条 / 17,139 行）。两份不是同一份数据，页面分开标注；阈值指纹 `4b70fc4d…` 两边一致。
- **第 4 步的互相关曲线**是演示用的简化特征（相邻帧灰度差能量），只用于直观展示时滞位置；是否允许修复以算子自身的门控统计量为准（图中第 ② 块，来自 `repair_manifest.csv`）。
- **可训练帧提升**：本机数据上是 4,985 → 8,881（+78.2%）。说明书中的 +90.1% 是平台数据的数字（4,571 → 8,691），引用时注明来源。
