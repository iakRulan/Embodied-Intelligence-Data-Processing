# RefSync-QA v3.2.2 变更说明（2026-10-25）

## 改了什么

新增三个帧级问题码（内容结构 · 阈值型 · 阻断训练），阈值逐路相机由参考集标定：

| 问题码 | 含义 | 判定 |
|---|---|---|
| `C_IMAGE_NOISE` | 画面噪声 / 花屏 | 噪声强度 > 参考集逐帧 99.9% 分位 × 3 |
| `C_IMAGE_EXPOSURE` | 曝光异常（过曝或欠曝） | 平均亮度 > 参考集 99.9% 分位 × 1.15，或 < 0.1% 分位 × 0.80 |
| `C_IMAGE_COLOR` | 色彩通道异常（疑似红蓝互换） | 整路判定：有颜色的帧里"主色偏暖"的占比 ≥ max(0.5, 参考集最高占比 × 10)，且有颜色的帧 ≥ 10 |

黑白屏、分辨率异常的帧已由 `C_IMAGE_SCREEN` / `C_IMAGE_SHAPE` 覆盖，不再重复判；判为噪声的帧不参与色彩判定。
`C_IMAGE_COLOR` 另写一条候选修复（整路交换红蓝通道后复检），不自动执行。

## 为什么

v3.2.1 发布后对 89 条测试集做了独立的逐帧画面扫描，有 4 条相机画面明显异常、却判为"通过、整段可用"，共 800 帧进入训练：

| 轨迹 | 现象 | v3.2.1 进入训练 |
|---|---|---|
| ep22 | 三路相机强彩色噪声（花屏） | 212 帧 |
| ep32 | 三路相机中度噪声 | 211 帧 |
| ep45 | 三路相机过曝 | 161 帧 |
| ep46 | 三路相机红蓝通道互换（蓝色货架变成橙黄） | 216 帧 |

原有画面检测只看黑白屏、清晰度、重复帧和马赛克：噪声反而让清晰度指标变高，过曝和通道互换的画面清晰度正常。

## 怎么算（`features._image_metrics`，每张图多 3 个量）

- `noise`：噪声标准差的稳健估计。灰度图经 3×3 算子 `[[1,-2,1],[-2,4,-2],[1,-2,1]]`（对平滑区域与直线边缘响应为 0），取响应绝对值的中位数 / 0.6745 / 6。中位数不受纹理影响。
- `satf` / `br`：饱和像素（max−min > 60）占比，以及饱和像素上 B−R 的均值。参考场景的主色是蓝色货架，`br` 恒为正；红蓝互换后变负。
- 平均亮度沿用已有的 `mean`。

## 阈值（20 条参考集，`calibration/default_thresholds.json`）

| 相机 | 噪声上界（参考 99.9% 分位） | 亮度范围（参考 0.1% ~ 99.9% 分位） | 色彩：参考集偏暖帧占比最高 |
|---|---|---|---|
| 场景 | 6.2（2.06） | 73 ~ 135（91 ~ 117） | 0.6% |
| 左腕 | 7.4（2.47） | 66 ~ 148（82 ~ 128） | 3.4% |
| 右腕 | 6.7（2.22） | 60 ~ 159（75 ~ 138） | 1.8% |

标定文件在 v3.2 的基础上只新增 `noise` / `exposure` / `color` 三组，其余阈值逐位不变；阈值指纹 `thresholds_sha256` 随之变化。

## 结果（赛题公开测试集 89 条，与 v3.2.1 逐条比对）

只有 6 条变化，其余 83 条的状态、问题码、评分、训练去向逐项相同：

| 轨迹 | 新增问题码 | 训练帧 |
|---|---|---|
| ep22 | `C_IMAGE_NOISE`（三路，噪声强度中位约 41，上界 6.2–7.4） | 212 → **0** |
| ep32 | `C_IMAGE_NOISE`（三路，噪声强度中位约 18） | 211 → **0** |
| ep45 | `C_IMAGE_EXPOSURE`（三路过曝，平均亮度中位 186–189） | 161 → **0** |
| ep46 | `C_IMAGE_COLOR`（三路有颜色的帧 100% 偏暖，参考集最多 3%） | 216 → **0** |
| ep09 | 另加 `C_IMAGE_EXPOSURE`（三路欠曝，平均亮度中位 48–51，下界 60–73） | 0 → 0 |
| ep35 | 另加 `C_IMAGE_EXPOSURE`（左腕 28 帧、右腕 1 帧过曝） | 0 → 0 |

- 需复核 64 → 68 条；通过 24 → 20 条；帧级问题行 6,910 → 7,730；问题区间 1,149 → 1,161。
- 可训练帧：不修不切 5,217 → 4,417；只检测 + 切段 7,741 → 6,941；检测 + 修复 + 切段 8,716 → 7,916。修复贡献的 975 帧与切段贡献的 2,524 帧不变。
- 修复后复检：需复核 58 → 62 条，问题行 6,389 → 7,209；修复 8 个副本 + 1 个元数据补丁、改写 807 格、拒修 35 项均不变；候选修复 28 → 29（ep46 的通道交换）。

## 验证

- `tools/selftest.py` 新增 4 个注入用例（每条基准轨迹）：37 噪声 σ=25（20 帧）、38 过曝（20 帧）、39 欠曝（20 帧）、46 整路红蓝互换。
  3 条基准轨迹共 132 / 132 个用例符合预期；新用例帧级 TP=20、FP=0、FN=0；全部行级用例 P=1.000、R=0.992（FN 6 为原有的画面停滞首帧）。
- 参考集留一检验 20 条：缺陷误报 0，价值提示 0。新增三项在留一检验里的余量：噪声最高到上界的 36%，亮度最高到上界的 92%、最低是下界的 1.17 倍。
- `tools/test_safety.py` 24 项（普通与 `-O` 模式）通过；`tools/regression_probes.py` 23 / 23 通过。
- `tools/selftest.py` 新增 `--part loeo|synthetic` 与 `--reuse`，可把留一检验和注入测试分开跑。

## 性能

`_image_metrics` 里马赛克判定的逐像素比较改为逐通道比较（结果逐位相同），饱和像素用逐通道最大最小值计算。
新版单张图的特征计算比 v3.2.1 快约 10%–25%；同一台 4 核 Linux 虚拟机上 89 条只检测 40.1 秒 → 33.7 秒，检测 + 修复 44.5 秒 → 42.3 秒。

## 影响

- 新阈值键使阈值指纹变化；不带 `noise` / `exposure` / `color` 的旧标定文件运行时，这三项记为"不可评估"，其余照常。
- 复赛平台提交的是 v3.2；本版本用于决赛演示与后续交付。
