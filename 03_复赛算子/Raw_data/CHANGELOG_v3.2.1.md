# RefSync-QA v3.2.1 变更说明（2026-10-23）

## 改了什么

新增帧级问题码 **`C_IMAGE_MOSAIC`**（内容结构 · 高置信 · 阻断训练）：画面成块马赛克 / 有效分辨率过低。

## 为什么

测试集 ep08 三路相机 256 帧全部是约 14×14 个色块拼成的马赛克（低分辨率画面按最近邻放大到 224×224）。
v3.2 的 `C_IMAGE_BLUR` 要求拉普拉斯方差与平均梯度同时低于参考下界才判模糊；马赛克的块边界是硬边，
拉普拉斯方差反而偏高（场景相机中位数 1,183，下界 1,057；腕部约 1,100，下界约 110），每帧 PNG 约 12 KB 也高于体积兜底线，
结果只命中场景相机 22 帧。其余 234 帧被当作有效帧，切出 165 帧进入训练片段。

## 怎么判

`features._image_metrics` 对每张图多算两个量：

- `flat`：水平、垂直相邻像素 RGB 完全相同的比例；
- `grid`：有像素变化（超过 2% 的行 / 列发生变化）的网格线占比。

`flat ≥ 0.6` 且 `grid ≤ 0.5`，并且不是黑白屏、分辨率异常的帧，判 `C_IMAGE_MOSAIC`。
阈值在 `config.FALLBACK_THRESHOLDS`（`mosaic_flat_min` / `mosaic_grid_max`），不依赖参考标定。

阈值依据（逐帧实测）：参考集 20 条 `flat` 最高 0.329、`grid` 最低 1.000；ep08 `flat` 0.94、`grid` 0.06；
过曝的 ep45 `flat` 最高 0.579、`grid` ≥ 0.97，不命中。

## 结果（赛题公开测试集 89 条，与 v3.2 逐条比对）

- 只有 2 条变化：
  - ep08：新增 `C_IMAGE_MOSAIC`（256 帧）；切段使用 165 帧 → **隔离回采 0 帧**；评分 97.42 → 80.00。
  - ep35：新增 `C_IMAGE_MOSAIC`；原本已因模糊、重复帧隔离，0 帧不变。
  - 其余 87 条的状态、问题码、评分、训练去向逐项相同。
- 帧级问题行 6,676 → 6,910；问题区间 1,147 → 1,149；需复核仍为 64 条（最强证据：高置信 8 → 9，阈值型 11 → 10）。
- 训练片段帧：检测 + 修复 + 切段 8,881 → **8,716**；只检测 + 切段 7,906 → 7,741。

## 验证

- `tools/selftest.py` 新增注入用例 36（主相机 20 帧马赛克）。基准轨迹 12 / 16 / 0 共 120 / 120 个用例符合预期，
  马赛克用例每次 TP=20、FP=0、FN=0；参考集留一检验缺陷误报 0 / 20。
- `tools/test_safety.py` 24 项（普通与 `-O` 模式）通过；`tools/regression_probes.py` 23 / 23 通过。
- 以上在 Linux aarch64、4 核、Python 3.10 上运行，用于功能核对，不作为计时依据。

- 复赛平台提交的是 v3.2；本版本用于决赛演示与后续交付。
