# RefSync-QA v3.2

## 1. 算法说明与提交摘要

具身智能多模态数据质量检测与安全治理算子

团队：MoMo_Lab。版本：RefSync-QA-v3.2。文档日期：2026-09-22。推荐策略：conservative。

本文用于出题方复赛算子审核，说明可执行实现、输入输出、算法方法、实际验证与能力边界。代码入口为 run.py；所有交付文件名、包内目录、部署示例路径均使用英文。文档正文保留中文，便于评委阅读。

### 核心思路

以正常参考数据标定统计阈值，以字段契约和数学约束检出确定性问题；把检测、质量评分、修复决策和训练准入分开。对有唯一依据的字段修正、证据门控的图像重对齐及严格受限的数值估计生成真实副本，回读审计后重新检测。对不可恢复部分输出质量掩膜、连续片段与人工候选，不修改原始采集数据。

处理链：输入预检 -> 元数据解析与标定 -> 单轨迹特征 -> 四类检测与五维评分 -> 条件修复 -> 回读审计和复检 -> 连续片段与安全去重 -> 报告和加载验收。

### 已完成的本地实测

| 项目 | conservative 默认结果 |
|---|---|
| 数据来源与划分 | 官方参考集 20 条、官方测试集 89 条；非随机划分 |
| 原始检测 | 24 条未标记、1 条仅价值提示、64 条需复核 |
| 实际治理 | 8 条 Parquet 副本、1 条仅元数据补丁 |

“未标记”不是确认正常；“需复核”不是官方真值异常。副本数不等于修复成功数。当前数据没有官方逐帧异常标签，也没有平台复赛数据的效果结论。

本地验证通过不等于平台部署通过。文件资源上传仅是资料交付；平台实际运行、管理员审核及复赛效果以平台记录为准。

## 2. 数据来源、字段契约与适用条件

### 来源与图片

20 条参考与 89 条测试来自组委会提供的数据包，沿用官方目录分组；不把测试轨迹加入正常标定。图片直接取自 Parquet 的 image、left_wrist_image、right_wrist_image 字段中的原始 bytes。随附 path 是图像标识；算法不联网下载图片，不生成场景画面，不读取 path 指向的外部文件来替代缺失 payload。

支持的数据形态为 LeRobot v2.1 目录，含 data/chunk-*/episode_*.parquet 及 meta/info.json、meta/episodes.jsonl、meta/tasks.jsonl。也可读取单个 Parquet，但缺少元数据时可评估范围会下降。默认相机为三路 PNG、分辨率 224 x 224 x 3；以实际元数据为先，并支持字段别名和布局配置。

| 字段 | 含义与检查 |
|---|---|
| timestamp | 公共时间戳；有限性、递增、间隔、单位和相对起点 |
| frame_index / index | 轨迹内帧号 / 全局索引；整数性、连续性、偏移一致性 |
| episode_index / task_index | 轨迹和任务身份；与文件及元数据一致性 |
| state / actions | 各 20 维；维度、有限值、数学约束、运动变化和统计残差 |
| 三路 image 字段 | bytes/path；可解码性、形状、画质、覆盖、相邻重复与运动 |

### 20 维布局依据

本地比赛规则明确给出两臂的 position-3、Rotation-6D-6、gripper-1 布局；不是从维度大小自行猜测。Python 切片如下，右端不包含：

| 分组 | 左臂 | 右臂 |
|---|---|---|
| 位置 | [0:3] | [10:13] |
| Rotation-6D | [3:9] | [13:19] |
| 夹爪 | [9:10] | [19:20] |

元数据 robot_type=panda 原样保留，不据赛题标题推断实际机器人硬件。位置绝对值上界 1.0、夹爪 [-0.05, 1.05] 为工程筛查假设，不是已验证硬件极限。新任务应先确认单位、归一化和动作语义；不适配的布局必须配置，不应直接套用。

合成故障仅在专用测试副本中注入，不混入真实 89 条统计。视频编码模态尚未完成解码验收，明确输出不可评估及阻断码，不当作已经验证的训练样本。

## 3. 特征提取、标定及时序与内容检测

每次特征提取只读取一次 Parquet、每张图片解码一次；修复后复检另行提取。数值列采用 Arrow/Numpy 解析。单轨迹处理失败记录 C_PROCESSING_ERROR，其余轨迹继续。

### 参考标定

随包 calibration/default_thresholds.json 使用全部 20 条参考标定，保存每条参考文件 SHA-256、轨迹 ID、各阈值来源及阈值核心哈希。提供 --reference 时现场重新标定；未提供则使用随包阈值。不可读参考不静默降为部分标定。

清晰度阈值按每路相机有效参考帧的 0.2% 分位数，分别乘 0.50、0.65、0.50 得到拉普拉斯方差、平均梯度和字节数下界。突跳阈值取参考 99.9% 分位数的 1.5 倍并设工程下限。价值比例在参考轨迹最大/最小值之外留 10% 裕量。数学契约、范围工程值和统计阈值分别记录，不混称“全部学习得到”。

### 时序

设标称周期 d0=1/fps，dt=t[i]-t[i-1]。dt<=0 标记重复/倒退；dt>1.5*d0 标记疑似掉帧；正间隔且非大缺口时，abs(dt-d0)>0.02*d0 标记抖动。结合 frame_index 的重复、倒序、跳号判断帧序问题，不只看 timestamp。

全局 index-frame_index 的众数需唯一且支持率至少 60% 才定位偏离行；自动修正另要求至少 90%。检查元数据长度、轨迹号和任务标签。检测单位倍数与相对 frame_index/fps 的整体偏移，但公共 timestamp 无法区分消息生成与记录时延。

### 图像与数值内容

| 检测项 | 实现与解释 |
|---|---|
| 结构 | 文件、字段、标量形状、维度、dtype、逐路图片形状；缺失与不可解析分开 |
| 画质 | 灰度暗/亮像素比例、对比度、拉普拉斯方差、梯度；按帧定位 |
| 模糊 | 拉普拉斯和梯度共同低于下界，或极低拉普拉斯/字节数；不称通用语义画质模型 |
| 重复 | 相邻图片 payload 哈希匹配；aHash 用于视觉多样性代理，不冒充近重复真值分类器 |
| Rotation-6D | 两个三维列向量的范数偏离 1、点积偏离 0；最大误差容差 1e-4 |
| 数值 | NaN/Inf、工程范围、相邻向量 L2 突跳、固定时移下分组残差 |

图像模糊、shape 等帧级标记同时进入对应维度的命中行比例，避免只用中位数清晰度遗漏稀疏问题。花屏、遮挡尚无独立专门正样本评测，不宣称覆盖充分。

## 4. 同步证据与 state/action 语义控制

### 三层同步证据

| 层级 | 可观测证据 | 能得出的结论 |
|---|---|---|
| 索引和覆盖 | path 帧号、frame_index、逐路头尾/中段缺图 | 证明索引/覆盖不一致；晚启动或早停止只作原因假设 |
| 统计时滞 | 腕部图像运动与本臂运动；跨相机运动相关 | 疑似相对错位；不能证明硬件时钟漂移 |
| 独立硬件时钟 | 本数据不具备逐传感器独立时间戳 | 不可评估，不输出虚构漂移量 |

图像运动信号为 64 x 64 灰度图的相邻平均绝对差；本体运动信号由对应机械臂变化构造。在最多正负 12 帧范围内搜索相关峰，使用参考集最佳时滞众数作基准，而非默认零时滞正常。

两路腕部都出现同向且相差不超过 1 帧的偏移，满足相关门槛后输出 S_VISUAL_KINEMATIC_LAG 并阻断整轨训练。仅一路偏离使用 S_CAMERA_LAG_SUSPECT 提示，不单独阻断。视觉近乎静止但机械臂在动的连续段输出冻结标记，长度以帧计。

这些是规则与统计证据，不是“同步正确率”。纹理、遮挡、任务阶段和相关峰歧义都可能影响判断；不足 60 帧等条件下不强行评估运动时滞。

### 不直接假定 state[t] 等于 action[t]

对每个 episode，在 lag=-3,...,3 中计算 action[i]-state[i+lag] 的每帧 RMSE，以全轨有效行平均 RMSE 最小的 lag 为唯一固定时移。有效配对至少 max(10, n//4) 行。随后用 RMSE 与位置/姿态/夹爪分组最大绝对残差阈值定位问题，并报告时移一致性。

该时移仅用于检测统计一致性，不自动平移或覆写 state/actions。禁止逐帧任意挑选最小残差，也不把参考中的正常控制滞后直接视作错误。

尽管规则给出布局，actions 的控制目标/时刻语义仍未被独立确认。残差问题属于需复核的统计标记；若平台数据采用不同控制语义，必须重新确认契约和标定，不能据残差证明物理故障或用 state 替代 action。

### 相机重对齐的额外门槛

自动移动真实图像 payload 除恒定 path 偏移外，还需匹配端点缺口、连续帧号和强统计证据：本臂相关 r>=0.6 或跨相机 r>=0.8，相关增益>=0.1、偏移相符、无强矛盾证据。弱场景相关只进入候选，不自动执行。重对齐仍是工程假设，复检通过不把它变成硬件时间真值。

## 5. 五维评分与数据价值评价

四类赛题问题映射到五个评分维度，均为 0-100 的可解释规则分。权重为结构 25%、时序 20%、同步 20%、内容 20%、价值 15%。每个问题码只归一个维度，同一根因触发不同码的多重影响仍可能存在，不宣称因果去重。

### 与代码一致的评分公式

对前四维 d，p[d] 为该维命中行占可读行的比例；e[d] 为该维 episode 级问题罚项之和，每个阻断码计 0.5、非阻断码计 0.1。

```text
score[d] = 100 * max(0, 1 - min(1, e[d] + a[d] * p[d]))
a[sync] = 2.0; a[structure, temporal, content] = 1.5
```

价值分从 100 起扣：高空闲 35、低交互 40、低视觉多样性 25、冻结/低信息 50，截断至非负。修复前后分数都不包含数据集级去重扣分，冗余剔除另列，避免修复后决策泄漏到修复前评分。

总分为可评估维度的加权均值；价值未完全可评估时 value_score 留空，另报部分分和可评估范围。文件不可读、空轨迹、处理异常为 0 分；必需字段缺失或未验收的视频模态总分上限 25；整路相机缺失上限 40。分数不能代替硬性训练门禁。

### 价值指标与分布

| 代理指标 | 用途 | 不代表什么 |
|---|---|---|
| idle_fraction | state/action 变化同时低于参考切点的比例 | 不直接等同无用；等待阶段可能合理 |
| interaction_rate | 至少一种运动超过参考中位切点的比例 | 不是任务成功率或高价值阶段真值 |
| visual_diversity | 有效帧 aHash 唯一比例 | 不等于物体、环境等语义场景覆盖 |
| 任务分布 | 包含 tasks.jsonl 声明但未出现的任务 | 不证明任务内阶段覆盖充分 |
| 全模态冗余 | 图片及 state/action 签名、顺序、任务、相对时间 | 图片重合不能单独证明可删训练轨迹 |

本地任务声明 2 类；原始任务可判断轨迹 42/45，其余 2 条不可判定。默认治理后任务帧数为 4,602/4,279，min/max=0.9298、归一化熵=0.9990，仅说明标签均衡。当前没有质量分与下游成功率、碰撞率的实测映射，不填写推测提升百分比。

## 6. 安全修复策略与拒修边界

原始文件只读；所有改动写到 governed 叠加层。修复分为契约修正、统计门控重对齐和估计补值三类，不能混称真实值恢复。

| 问题 | 自动执行条件与做法 | 拒修或保留风险 |
|---|---|---|
| 身份与索引 | 元数据唯一确定 task/episode；index 众数唯一、支持率>=90%、帧号连续 | 证据冲突或偏移并列不选边 |
| 存储类型 | 无损转换到 info.json 声明类型；schema 单列审计 | 有损精度降低不做 |
| 时间单位/起点 | 连续帧号、唯一合理单位/基准变换、残差在容差内；保留变换后抖动 | 起点可能有真实含义；不证明原时钟正确 |
| 相机恒定偏移 | 索引、端点、帧序与强相关共同支持；移动既有 bytes，缺失端置空 | 不补造缺图；弱证据只给候选 |
| 稀疏 NaN/Inf | 受影响行<=10%、连续缺口<=2、两侧可信且帧号连续；逐分量插值或 Rotation-6D 约束解 | 首尾、长缺口、乱序、坏邻域拒修；解仍为估计 |
| 单帧位置越界 | 邻帧可信且连续，只对越界分量取邻帧均值 | 连续越界不做；工程界限非硬件边界 |
| 元数据长度 | 按实际可读行数生成补丁 | 不改官方 meta，不造缺失帧 |

默认 conservative 不按标称周期重建缺失或抖动时间。nominal 必须显式选择，按 frame_index/fps 规整，只能称“标称契约时间”，不能称恢复真实采样时刻。off 禁止时间改写。

黑屏、模糊、坏图片、长段缺失、全段姿态噪声和未确认的本体时间移位，以隔离、切段、候选方案或回采处理，不用生成图像或任意平滑掩盖证据。

### 写入与审计

写副本前核对源/目标路径边界，临时文件写入后逐格回读。每条审计含 row、field、original_value、repaired_value、method、issue_code。图像字典核对 bytes 哈希、长度与 path；schema 类型及元数据变化单列；int64 原值精确比较，不转 float64 后比较。审计缺失、原值伪造、新值不符或额外改动均拒绝落盘。

manifest 记录原始/副本 SHA-256，复检重算问题码和分数。哈希证明文件完整性，不证明估计值是真值。估计行标记 estimated_repair，涉及估计的整轨样本权重上限 0.5；未修改分量保持原值和类型。

## 7. 治理、训练准入及输出接口

### 训练门禁不由总分单独决定

复检无阻断码 -> frame_valid -> 帧号连续且至少 min_clip 帧 -> 严格同任务去重 -> train_keep。默认 min_clip=30；动作窗口更长时应同步提高，窗口不得跨 clip。低价值提示本身不删除帧，可降权。

去重优先保留可用帧较多、分数较高的轨迹。仅在相同已知任务、全模态签名和顺序匹配、相对时间一致（容差 1e-5 秒）、候选整片段被一个已保留片段直接连续覆盖时删除。不通过传递分组或拼接多个覆盖源删独有上下文。哈希签名是工程内容标识，不是对恶意碰撞的证明。

默认 frame_valid=9,863 行；最终 train_keep=8,881 行，其差 982 行因片段条件不能直接用于训练。最终去重剔除为 0 帧，表示未满足严格可删条件，不代表不存在图像重合。

### 文件输出与消费约定

| 文件，均相对于 output | 内容与使用方式 |
|---|---|
| report/summary.json | 分母、分布、覆盖边界、效率、质量总览 |
| report/episode_report.csv | 全量每轨迹问题码、五维分、前后状态、治理建议 |
| report/frame_flags.csv | 原始/最终阶段逐帧问题和最终保留标记 |
| report/issue_intervals.csv | 连续问题区间；定位回原始行 |
| report/issue_code_dictionary.csv | 类别、证据强度、范围、是否阻断训练 |
| report/thresholds_used.json | 实际阈值、参考 ID、哈希和来源 |
| governed/repair_manifest.csv | 修复文件、前后 SHA-256 和复检结论 |
| governed/repair_audit.csv | 单元格与 schema 改动审计 |
| governed/repair_candidates.csv | 未自动执行的候选，供人工决定 |
| governed/quality_masks/ | 逐帧有效性、估计、权重和 clip 归属 |
| governed/clips.csv | 可训练连续片段边界、来源和权重 |
| governed/mask_index.csv | 每轨读取原文件或副本的映射 |

governed 仅含被修改的 Parquet，不是独立完整数据集。训练端应使用 tools/load_governed.py 的 iter_clips(dataset, output)，对原数据叠加副本，验证来源路径、行数、连续帧号、递增时间、掩膜和权重。检查为显式异常，python -O 不会关闭。

完整问题码、片段及逐格审计在运行后自动输出；提交包中的 validation/full89_episode_report.csv 为已有 89 条本地验收报告，不冒充平台复赛报告。

## 9. 评估协议、复验结果与效果边界

| 验证层 | 设计 | 结果 |

## 10. 平台运行、审核方法与交付边界

解压后进入 refsync_qa_v3_2，以普通 CPU 运行，无需 GPU、模型权重或外部服务。算法运行不联网；首次安装依赖可能需要包镜像或预制环境。requirements.txt 为兼容范围，不是全部组合验证承诺；Dockerfile 是可选示例，尚不能视作已通过平台镜像构建。

```bash
python -m pip install -r requirements.txt
python run.py --input /data/test --output /data/result --workers 4 --strict
python tools/load_governed.py --dataset /data/test --output /data/result
```

需要重新标定时追加 --reference /data/reference。平台无命令参数启动时配置 RSQA_INPUT、RSQA_OUTPUT、RSQA_REFERENCE（可选）和 RSQA_WORKERS。输入与输出目录不得相同或互相包含；建议数据只读挂载，结果目录可写。Windows 对应英文示例 H:/refsync_data/test 与 H:/refsync_results/run_001。

退出码 0 表示批处理完成，不表示全部无异常；2 表示输入、配置或路径预检失败；使用 --strict 且有处理异常时返回 3。再次运行默认归档旧 report/governed，不覆盖历史；审核时不用 --clean-previous。

### 出题方建议审核顺序

1. 校验 submission_manifest.json 所列文件 SHA-256，确认 run.py、calibration、refsync_qa 与文档版本一致。
2. 普通模式和 python -O 各运行 tools/test_safety.py；可在无赛题数据时验证边界防护。
3. 用平台数据只检测一轮（--no-repair），核对字段、任务和不可评估项目；再用新目录运行默认保守治理。
4. 查看全量 episode_report、frame_flags、issue_intervals，不只看总分或精选案例。
5. 回读修复副本、审计原值和新值、哈希与掩膜；通过 load_governed 实际加载，不把“生成副本”当成恢复成功。
6. 在独立标签下统计分类别 P/R/F1 与误报；在固定训练配置下测下游收益。
